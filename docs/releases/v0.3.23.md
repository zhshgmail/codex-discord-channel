# v0.3.23 — Cross-channel sender allowlists

Source candidate based on v0.3.22. Not tagged or installed by this change.

An explicit `groups["*"]` policy enables trusted senders in channels and threads
without enumerating destinations. An omitted/empty wildcard sender list inherits
the instance's top-level `allowFrom`; if both lists are empty, admission remains
closed. Top-level DM behavior is unchanged. Exact channel/thread policies take
precedence, followed by thread parent policy, then the wildcard. Bot and mention
checks remain in force. History uses the same policy selection and sender list,
with its existing own-bot and mention exceptions; voice/stage history remains
unsupported.

Validation on the source candidate:

- Access-policy suite: 26 passed, zero failures/cancellations/skips.
- Added handler and history coverage: denied senders cause no reference fetch or
  enqueue; admitted sources preserve their actual thread destination; history
  excludes unknown authors while retaining allowed peers and own-bot readback.
- Five focused wildcard/precedence tests passed. New regression cases fail
  against the unchanged v0.3.22 access implementation.
- `npm run build` and `npm run check`: 379 passed, zero failed/cancelled;
  100 existing explicitly retired contracts skipped. Syntax, generated runtime
  parity and smoke checks passed.
- Local independent source review found no new access bypass; its documentation
  and integration-coverage findings were addressed.

This does not repair Codex host input latency during compaction and does not
claim live wildcard acceptance. Existing channel/thread delivery was checked
separately on the still-running v0.3.21 generation. Runtime installation,
activation, restart, and real-message acceptance remain separate.
