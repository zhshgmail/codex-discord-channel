# v0.3.22 — Source-bound Discord reply reminders

Source release candidate, relative to v0.3.21. This change does not publish a
tag or install, activate, restart, or remove any alias runtime.

- Every admitted Discord source carries a plugin-generated reminder outside
  the channel body. It binds the exact channel and reply-parent IDs to the
  instance-scoped MCP sender and requires exact-destination readback before
  claiming delivery. Console output is explicitly not Discord delivery.
- Body and attachment text are escaped in the envelope to prevent literal
  closing tags from impersonating the plugin reminder. The original normalized
  and persisted source bytes are unchanged.
- Start, steer, reconnect, and post-rotation delivery reuse the same envelope.
  No timer, extra model turn, automatic forwarding, account-selection logic,
  queue migration, or receipt-policy change is introduced.
- Package, plugin/cache identity, MCP server and app-server client versions,
  generated bundles, packaging checks, and installation examples name 0.3.22.
  The existing node-from-PATH MCP manifest remains unchanged.

## Upstream integration

Includes upstream main `2d0d3c5390064378dcd7851166d02cc0f3f35872` (v0.3.21):

## Causal and deployment limits

This establishes a structural per-message reminder and literal envelope
boundary. It does not prove that the model will always send replies, that
long-context forgetting is fixed, or that semantic prompt injection cannot
influence the model. Long-context response efficacy remains UNMEASURED.

Evaluate matched old/new consumer contexts for omitted replies, wrong reply
parents, duplicate replies, and response latency before making behavior claims.
Disk staging is not activation or live delivery. Preserve the running generation,
old directories, queues, receipts, policy, and account binding; activate only the
owner-selected alias in its accepted maintenance window. No other alias is part
of this source update.
