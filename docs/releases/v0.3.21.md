# v0.3.21 — Reliable interrupt cleanup and terminal restoration

Changes relative to v0.3.20:

- Repeated terminal Ctrl+C can no longer interrupt the launcher's Node ownership
  verifier during cleanup and strand an app-server generation. Cleanup helpers
  run through `setsid --wait`, preserving their real exit status and all existing
  instance, PID/start-time, process-group, and socket identity checks.
- The launcher saves the original terminal settings before starting children
  and restores them after cleanup, including normal exit and termination. This
  fixes keyboard input remaining invisible when the TUI leaves echo disabled.
  Existing terminal customizations are preserved.
- The MCP manifest uses `node` from `PATH` instead of a developer's absolute
  executable path. Make Node 22.15 or newer available in the launching shell.
  Instance `account.env` still requires absolute `NODE_BIN` and `CODEX_BIN` paths.
- Installation instructions point to the actual release tag and cache version.

## Validation

- `npm run check`: 373 passed, 0 failed, 0 cancelled; 100 explicitly retired
  session-bound contract tests skipped. Syntax, runtime bundle parity, and smoke
  checks also passed. The packaging test launches the actual distributed MCP
  command from a copied cache with no `node_modules` and an isolated account.
- Six real Codex 0.153.3 terminal exit/relaunch cases passed on Linux with Node
  24.14.1 using the same launcher implementation. Tests covered ready exits,
  interruptions at 150/500/1000 ms, and restart after those interruptions. No
  generation processes, socket, or manifest remained; exact terminal settings
  were restored. Cleanup took 0.3–1.4 seconds.
- The concurrent-instance regression uses real OS processes with separate
  account/state directories and simulated bot settings. Interrupting and
  relaunching one instance leaves the other's PIDs, start times, socket inode,
  and manifest unchanged. This is not a two-real-bot integration test.
- Two live owner DMs were verified as rendered user prompts in the selected
  TUI's tmux pane, with one durable source record and one reply receipt each.
  Discord history verified the outbound ID, destination, reply reference,
  content, and bot author. This check used the local 0.3.21 development build.

## Scope and upgrade

This release fixes the reproduced cleanup race and terminal restoration defect;
it does not establish that every historical ownership conflict has the same
cause. Long-running stress tests and live delivery after `/clear` remain outside
this release's completed acceptance scope. Correcting an initial DM allowlist
was an instance configuration change, not a transport code change.

Upgrade one selected instance at a time from an ordinary shell after its TUI
exits. Preserve its queue, receipts, access policy, and account binding. Do not
install over a running instance or kill processes belonging to other instances.
No Linux reboot is required. See the root README for pinned installation steps.
